# Demo video: shot list and narration

The video must run under 2 minutes, and judges may judge from it alone, so the best moment comes first. The plan below
runs 1:55: about 110 seconds of narration and a 5-second end card.

Every shot is a URL on the web UI, so each take can be repeated exactly. Append the query string to the base URL:

- local: `uv run pitchside serve`, then `http://127.0.0.1:8000/` + the query;
- deployed: `{{static_web_app_url}}` + the query (once the Static Web App exists, see [AZURE.md](AZURE.md)).

The URLs below use the three sample runs in `web/data` (`comeback`, `faults-demo`, `siege`). The "On screen" notes
describe the **offline samples (fake model client)** as they are today, checked in Chromium on 2026-10-23. Moment ids
and times come from the deterministic stats engine, so they stay the same when live bundles of the same matches
(same seed, storyline and clubs) replace the samples. Only the model-written texts change. `uv run pytest
tests/test_demo_doc.py` checks every URL in this file against `web/data`.

## Setup

- Browser at 1920 x 1080, full screen (F11), so no URL bar, bookmarks, profile picture or notifications are in the
  frame. Use a clean browser profile.
- Decide which data you are recording before you start: **live bundles** (the badge reads "Recorded run generated by
  the live pipeline") or the **offline samples** (the badge reads "Offline demo (fake model client)"). The narration
  has a line for each case. Read only the lines that match the badge on screen.
- Keys used in the takes: `E` evidence for the current moment, `L` next language, `Esc` closes a drawer, `I` run info
  (close the drawer first), `Space` play or pause, `2` analyst view.
- Record each shot as a separate take and cut them together. The URLs mean no take depends on the one before it.

## Honesty: what to say about offline and live runs

- **Today every sample in `web/data` is an offline run** on the fake model client. If the video uses them, read the
  OFFLINE lines, never say that a model wrote the texts, and do not present the `[es · offline]` texts as Spanish.
  The stats, findings, checker, workflow, fallbacks and audit trail in those runs are real code. Only the wording is
  a stand-in.
- **A live bundle is still a recording.** Say "recorded run", not "live": the page replays a bundle and calls no model
  (the run info panel says so). The badge "Recorded run generated by the live pipeline" appears only for a Foundry run.
- **Faults are injected on purpose.** The failures in `faults-demo` are simulated by the fault injector. The recovery
  is the real pipeline. Say "injected deliberately", and keep the faults badge in frame.
- **Cost:** offline, the model usage panel shows token estimates ("not real spend"). Do not quote them. Quote cost only
  from the live usage log (`uv run pitchside cost`), as measured.
- **Quality:** the offline evaluation is a plumbing check, not model quality. Do not say the system is never wrong.
  The checker guarantees that shown numbers match the evidence, and the verifier is a model's judgement. If you quote a
  grounding figure, use the hand-labelled spot check from [LIVE_EVAL.md](LIVE_EVAL.md).
- **Detector:** do not say it finds every key moment. Goals are found every time on held-out seeds; counter-attacks
  and chaos spells are weaker (README, "Stats engine and how well it works").
- **The pitch is not tracking data.** The ball path is drawn from event locations.
- **Azure:** name only services that are deployed on recording day (Rules 4.3: the project must work as shown). An
  Azure portal shot must be cropped so that no subscription id, tenant, account e-mail or directory name is visible.
  The run info panel of a live bundle shows the MCP server URL and the deployment names, so crop or blur that row if
  you show it.
- **No real names or marks** in the frame: clubs and players are invented, crests are generated, and the browser is
  full screen.
